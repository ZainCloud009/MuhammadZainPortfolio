Cloud Architecture

From cloud concepts to hands-on AWS exploration.

Cloud computing becomes much easier to understand when the definitions are connected to real services. In this article, I break down the foundations of cloud computing and share the key takeaways from exploring AWS through a Free Tier sandbox.

By Muhammad Zain Module 1 · Cloud Computing Foundations 8 min read AWS EC2 · S3 · VPC · IAM

What cloud computing changes

Cloud computing delivers servers, storage, databases, networking and software over the internet on demand. Instead of purchasing and maintaining physical hardware, teams can rent the capacity they need from a cloud provider and pay for what they use.

This model gives organizations the freedom to launch resources quickly, scale them when demand changes and avoid maintaining infrastructure that is no longer needed. AWS was the cloud provider explored in this module.

Key Takeaway: Cloud platforms turn infrastructure into an on-demand programmable service, allowing technical teams to focus on shipping software and improving applications rather than managing server hardware.

The three cloud service models

Cloud services are commonly grouped by how much of the technology stack is managed by the provider versus the customer.

I

IaaS

Infrastructure as a Service provides virtual servers, storage and networking. The customer manages the operating system, middleware and application. Examples: Amazon EC2 and EBS.

P

PaaS

Platform as a Service provides a managed environment for building and running applications without managing the lower-level infrastructure. Examples: Elastic Beanstalk and Lambda.

S

SaaS

Software as a Service delivers ready-to-use software through the internet. Examples include Gmail, Salesforce, Amazon Chime and Amazon WorkMail.

Regions, Availability Zones and virtualization

A cloud Region is a geographic area that contains multiple isolated Availability Zones (AZs). Each Availability Zone consists of one or more discrete data centers with independent power, cooling and networking. This architectural separation makes it possible to design applications for high availability and fault tolerance.

Virtualization is the core technology behind much of Infrastructure as a Service. A hypervisor lets one physical host run multiple isolated virtual machines, enabling providers to share compute resources efficiently while keeping customer workloads securely separated.

The four building blocks I explored

Compute

Processing power for workloads. Core AWS examples: Amazon EC2 virtual servers, AWS Lambda serverless functions and AWS Elastic Beanstalk managed hosting.

Storage

Data persistence through Amazon S3 scalable object storage, EBS persistent block storage for EC2, and S3 Glacier for compliance archiving.

Networking

Securely isolating and connecting cloud resources with Virtual Private Clouds (VPC), public and private subnets, internet gateways, route tables and Route 53 DNS.

Security

Protecting identities, data and infrastructure with AWS Identity and Access Management (IAM), Security Groups, Network ACLs and encryption at rest and in transit.

Scalability, elasticity and cloud pricing

Scalability is the planned ability to increase capacity for a growing workload, for example by using larger servers (vertical) or adding more instances (horizontal). Elasticity goes further by automatically scaling resources up and down in response to real-time traffic demand. AWS Auto Scaling is a practical example of elasticity in action.

  • Pay-as-you-go: Pay only for the resources consumed per second or hour, without upfront capital commitment.
  • Reserved Instances & Savings Plans: Commit to a one- or three-year period to significantly reduce costs compared with on-demand pricing.
  • Spot Instances: Take advantage of spare AWS compute capacity at up to 90% discount for fault-tolerant workloads.
  • Free Tier: Access selected learning and light-use services without charge during the first 12 months, subject to monthly limits.

Translating services across major cloud providers

Different providers use different brand names, but the underlying cloud capabilities are often equivalent. This table helped me connect AWS terminology with Microsoft Azure and Google Cloud.

Capability AWS Microsoft Azure Google Cloud
Compute Amazon EC2 Virtual Machines Compute Engine
Object storage Amazon S3 Blob Storage Cloud Storage
Serverless AWS Lambda Azure Functions Cloud Functions
Identity & access AWS IAM Entra ID (Azure AD) Cloud IAM
Free tier 12 months + always-free tier $200 credit / 12 months $300 credit / 90 days

What I did in the AWS Free Tier sandbox

The hands-on part of the module focused on navigating the AWS Management Console and connecting theoretical concepts with actual infrastructure configurations:

  • EC2: Configured security groups, key pairs, and launched Linux instances within Free Tier limits.
  • S3: Created S3 buckets, configured bucket policies, versioning, and explored life-cycle rules.
  • VPC: Inspected default VPC configurations, routing tables, and subnets across availability zones.
  • IAM: Created non-root IAM users with least-privilege policies, enforced MFA, and reviewed security best practices.
  • Billing & Budgets: Configured zero-spend budget alerts to actively monitor Free Tier limits and prevent unexpected costs.

My biggest takeaway

Opening the AWS Console made the relationship between cloud concepts much more concrete. EC2 clarified the IaaS model because it exposes configurable virtual infrastructure. Managed services such as Elastic Beanstalk showed how a platform approach reduces operational work, while SaaS demonstrated the experience of consuming a complete application.

At first, the sheer number of AWS services and settings felt overwhelming. Exploring EC2, S3, VPC and IAM one at a time made their individual roles clear and demonstrated how they seamlessly connect to form reliable, scalable cloud infrastructure.
