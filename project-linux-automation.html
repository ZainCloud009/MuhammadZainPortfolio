bash-automation-suite.sh — Amazon Linux (Production) 
#!/usr/bin/env bash
# Production Backup & S3 Offsite Sync Automation
set -euo pipefail

TIMESTAMP=$(date +"%Y%m%d_%H%M%S")
BACKUP_DIR="/var/backups/production"
S3_TARGET="s3://mz-enterprise-backup-vault/daily-dumps"

echo "[$(date '+%T')] Initiating automated system maintenance..."

# Step 1: Export compressed MySQL database
mysqldump --single-transaction --quick app_db | gzip > "${BACKUP_DIR}/app_${TIMESTAMP}.sql.gz"

# Step 2: Encrypted sync to Amazon S3
aws s3 cp "${BACKUP_DIR}/app_${TIMESTAMP}.sql.gz" "${S3_TARGET}/" --sse AES256

# Step 3: Rotate logs and purge old archives
find /var/log/app -name "*.log" -mtime +3 -exec gzip {} \;
find /var/log/app -name "*.gz" -mtime +14 -delete

echo "[$(date '+%T')] System maintenance finished with 0 errors. ● Ready"

Project Overview & Operational Goals

Routine systems administration often suffers from human error when maintenance chores are executed manually. This project implements a comprehensive Linux automation suite for Amazon Linux instances, replacing manual administrative interventions with error-trapped, self-healing Bash scripts scheduled through cron daemons.

Core Automation Workflows Developed

Three mission-critical administrative workflows were created and deployed into production:

  • Database Backup & S3 Synchronization: Scheduled nightly cron jobs dump production MySQL databases using --single-transaction flags, compress archives with gzip, and stream them directly into encrypted Amazon S3 buckets via the AWS CLI with retention lifecycle policies.
  • Proactive Log Archival Daemon: Automatically scans /var/log and web application log directories, compresses logs older than 3 days, and purges archives exceeding 14 days to prevent server outages caused by full root partitions.
  • Disk & Memory Health Watchdog: Hourly scripts inspect partition utilization and available RAM, sending alerts if storage usage surpasses safe operational thresholds (85%).
Defensive Scripting Standard: All shell scripts enforce set -euo pipefail, parameter expansion validation, and trapped cleanup signals to ensure scripts fail safely without leaving orphaned lock files or incomplete archives.

Server Administration & Hardening

In addition to automation scripts, complete Linux instance administration was configured:

  • Security Hardening: Enforced SSH key-based authentication with root login disabled, non-standard port configuration, and firewall rules configured via iptables.
  • Web Server Configuration: Installed and managed Apache HTTP Server (httpd), configuring Virtual Hosts, custom error pages, and mod_rewrite rules.
  • Service Reliability: Created custom systemd service unit files with auto-restart policies on failure to ensure continuous service uptime.

Key Results & Efficiency Gains

The automation suite eliminated over 6 hours of manual maintenance weekly, maintained 99.9% database backup consistency, and successfully prevented disk full alerts across all monitored Amazon Linux servers.
