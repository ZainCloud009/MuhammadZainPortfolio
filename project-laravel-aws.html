Laravel 12 Cloud Architecture: AWS ECS, Dynamic Port Mapping & CI/CD

Project Overview & Migration Motivation

Deploying Laravel applications on a single EC2 instance using manual SSH commands or standalone Docker containers works fine initially, but as traffic and release frequency grow, it becomes brittle. Engineering teams face downtime during code updates, port conflicts when restarting containers, and sluggish deployment pipelines.

This project modernizes the application into an enterprise cloud architecture on AWS Elastic Container Service (ECS) using the EC2 Launch Type, automated through GitHub Actions and fronted by an AWS Application Load Balancer (ALB) with SSL termination.

The Port Conflict Problem & Dynamic Port Mapping

When deploying containers with static port binding (hostPort: 80), rolling updates fail with CannotStartContainerError: Error starting userland proxy: listen tcp4 0.0.0.0:80: bind: address already in use. ECS attempts to bring up the updated container before terminating the old one, leading to port collision.

  • Dynamic Ephemeral Ports (hostPort: 0): By specifying port 0 in the ECS task definition, the Docker daemon automatically assigns an unused port from Linux's ephemeral range (32768–65535).
  • Dynamic ALB Target Group Registration: ECS registers the new task on its ephemeral port with the ALB Target Group.
  • Zero-Downtime Traffic Shifting: The ALB validates health checks on the new port, shifts traffic seamlessly, and drains old tasks without dropping a single active HTTP connection.

High-Performance Multi-Stage Containerization

To keep container images secure and compact, we implemented a 3-stage Docker build:

  • Stage 1 (Frontend): Compiles Vite and Tailwind assets via Node 22 Alpine, copying only compiled static assets into the final image.
  • Stage 2 (Composer Builder): Installs production PHP packages with optimized autoloader classmaps, stripping out development tools.
  • Stage 3 (Production Runtime): Ultra-lightweight PHP 8.2-FPM Alpine image bundled with Nginx and Supervisord, running an automated entrypoint.sh that caches configuration, routes, and views on boot.

Enterprise Database Security: AWS RDS MySQL SSL

Transit encryption was hardened by embedding the official Amazon RDS CA bundle (rds-ca-bundle.pem) directly into the container runtime. The Laravel database configuration enforces PDO::MYSQL_ATTR_SSL_CA and validates server certificates, ensuring encrypted transit between ECS compute tasks and the managed RDS MySQL database within the AWS VPC.

High-Speed GitHub Actions CI/CD & 30-Second Rollouts

Traditional deployment pipelines often take 15 to 20 minutes. This architecture achieves sub-4-minute delivery and 30-second container rollouts:

  • Concurrent Test & Build: PHPUnit automated testing and Docker image compilation/pushing to Amazon ECR run simultaneously in parallel GitHub Actions runners.
  • Docker Layer Caching: Uses GitHub Actions cache backend (type=gha) for rapid image builds.
  • Optimized ALB Target Group: Deregistration delay was reduced from 300 seconds down to 5 seconds, paired with 5-second interval health checks. Rolling deployments complete in approximately 30 seconds on ECS.
